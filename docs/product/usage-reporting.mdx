title: Usage reports and CSV exports
description: Choose deterministic accounting periods and reconcile exported usage with the Analytics page.
---

Open **Settings → Analytics → Billing** to report model and sandbox usage.

## Scope

Choose **Personal** or **Organization** before selecting a period. Personal reports contain only the signed-in user's usage and are available to every member. Organization reports require an organization admin. Team scope is not offered because Valet does not currently have a general usage-team membership model; reports are never labeled as team-wide unless that scope can be enforced.

## Period rules

Usage reporting uses **UTC**. Every period is **start inclusive and end exclusive**, written as `[start, end)`. An event at the start timestamp is included. An event at the end timestamp belongs to the next report.

- **1d, 7d, and 30d** are rolling windows ending when the report request runs.
- **Month** includes an exact completed UTC calendar month. Month length is determined from the calendar, including February 29 in leap years.
- **Custom** accepts UTC calendar dates. The start date is included and the end date is excluded. To include all of March 31, use April 1 as the end date.

Current or future calendar months are rejected because they are not complete. A custom end can be the next UTC midnight so the current UTC day can be included. Invalid dates, equal/reversed boundaries, and ranges farther in the future show a validation error. A valid period with no usage returns zero totals and empty breakdowns.

UTC does not shift at daylight-saving transitions. A custom report from `2026-03-08` to `2026-03-09` is exactly the UTC day `[2026-03-08T00:00:00Z, 2026-03-09T00:00:00Z)`.

## Sandbox time

Valet records new sandbox active-time flushes as intervals. Reports clip these intervals to the selected `[start, end)` period with millisecond precision. Reports split intervals at UTC day boundaries.

Deploy migration `0032` before the worker when possible. Its trigger records increments from old and new workers during a rolling deploy. If worker code deploys first, active-time writes continue in the lifetime counter and later backfill preserves them as legacy usage. Usage report requests fail until the migration creates the interval table.

Historical `active_seconds` values do not contain activity timestamps. The migration keeps these totals and attributes each total to its session creation date. The page, API response, and CSV identify this legacy limitation. Therefore, sandbox totals that include activity from before interval tracking are not exact calendar-period totals.

## Export and reconciliation

Select **Export CSV** to export the scope and period currently shown. For rolling reports, the page sends the displayed report's exact end timestamp so the export replays the same window instead of advancing with the clock. The server serializes the same aggregate response shape used by the page; it does not run a default-window fallback. The file name and every row contain an unambiguous period label such as `calendar-month_2024-02_UTC` or `date-range_2024-01-15_2024-02-01_UTC`.

The first row is the report total. Remaining rows reproduce the daily, origin, workflow, model, user, and user-by-model breakdowns. The header is stable:

```text
period_label,period_start,period_end,timezone,boundary,scope,sandbox_usage_semantics,breakdown,dimension,secondary_dimension,input_tokens,output_tokens,total_cost_usd,call_count,session_count,sandbox_cost_usd,sandbox_active_seconds,percentage,total_users
```

All cells are quoted for spreadsheet compatibility. Blank numeric cells mean that the metric does not apply to that breakdown, not zero. The total row matches the hero metrics. Daily and user rows include sandbox-only usage and use each user's configured sandbox size, so their sandbox seconds and costs sum to the total. Origin, workflow, model, and user-model rows describe model usage only.

This report exposes existing usage aggregates. Provider/team/monthly ledger attribution is tracked separately and is not created or modified by this export.
