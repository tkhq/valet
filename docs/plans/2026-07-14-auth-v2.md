# Auth v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real authentication for the v2 stack per `docs/specs/2026-07-14-auth-v2-design.md`: better-auth (email/password + social + OIDC SSO + API keys + MCP OAuth server), invites with domain admission, sandbox tokens + service-JWT primitives, keeping the dev stub as the last middleware rung.

**Architecture:** One better-auth instance (Drizzle adapter over the existing better-sqlite3 app db) mounted at `/api/auth/*` on Hono. Valet-owned modules in `packages/api/src/auth/` handle config, provisioning hooks, invites, sandbox tokens, and the `/mcp` endpoint. `authMiddleware` stays the single place that sets `c.var.user`.

**Tech Stack:** better-auth@1.6.23, @better-auth/sso@1.6.23, @better-auth/api-key@1.6.23, @modelcontextprotocol/sdk, Hono 4, Drizzle + better-sqlite3@12, React 19 + TanStack Router.

**Files:**

- Test: `packages/api/src/auth/provisioning.test.ts`

**Interfaces:**

- Produces:
```ts
export type Admission =
  | { allowed: true; role: "admin" | "member"; inviteId?: string }
  | { allowed: false };
export function evaluateAdmission(db: Db, cfg: AuthConfig, email: string, inviteCode?: string): Admission;
// order: zero users in db → { allowed: true, role: "admin" }
//        email domain ∈ cfg.allowedEmailDomains → { allowed: true, role: "member" }
//        valid invite by code, else by email → { allowed: true, role: invite.role, inviteId }
//        else { allowed: false }

export interface ProvisioningDeps { db: Db; cfg: AuthConfig; credentialStore: CredentialStore; }
export function buildAuthHooks(deps: ProvisioningDeps): {
  beforeHook: ReturnType<typeof createAuthMiddleware>;   // for betterAuth({ hooks: { before } })
  databaseHooks: BetterAuthOptions["databaseHooks"];     // user.create.before/after + account.create.after
};
```
- Hook behavior (spec §Provisioning, exact):
  - `beforeHook`: only acts on `ctx.path === "/sign-up/email"`; reads `ctx.body?.inviteCode` and `ctx.body?.email`; on `{ allowed: false }` → `throw new APIError("FORBIDDEN", { message: "an invite is required to join this deployment" })`.
  - `user.create.before(user, context)`: derive flow from `context?.path` — `"/sign-up/email"` and null-context pass through (already gated / internal); social paths (`"/callback/"` prefix or `"/sign-in/social"`) re-run `evaluateAdmission` with `user.email` and NO code, return `false` when denied; SSO paths (`"/sso/callback/"` prefix) always allowed. Always return `{ data: { ...user, role } }` with the admission-resolved role (SSO non-first-user → `"member"`).
  - `user.create.after(user, context)`: ensure the org row exists (reuse the existing org bootstrap in `services/org.ts` — if none exports it, add `ensureOrg(db): { id: string }` there); insert `org_members` row `{ orgId, userId: user.id, role: user.role }`; if the admission matched an invite, `acceptInvite`. Pass the matched inviteId from `before` to `after` via a module-scoped `Map<email, Admission>` keyed per call (both hooks run in the same request; clear the entry in `after`/on failure).
  - `account.create.after(account)`: if `account.providerId` is `"google"` or `"github"` and `account.accessToken` is set, write to the credential store: service `"google"` → `{ type: "oauth2", accessToken, refreshToken? }` for the Google plugins' service name, service `"github"` → same for github (match the service names the plugin fleet's credential declarations use — check `packages/plugin-github/src/plugin.ts` and the google plugins' manifests; store via the same path `PUT /api/credentials` uses in `routes/credentials.ts`).
