# Model Comparison Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only table every member can open that lists the org's active models with list prices, context, benchmark scores, our own eval pass rate, and two derived indices (Quality, Value), reachable from the personal rail and as an org "Compare" tab.

**Architecture:** A dated benchmark snapshot (JSON data + typed matcher) lives in `@valet/shared`. The web page joins `GET /api/models` (already member-visible) with the snapshot client-side; pure helpers compute Quality and Value. A Node script turns an eval-runner JSON report into a family's `valetEval` block. No new API, no new dependency.

**Tech Stack:** TypeScript, React 19, TanStack Router (file routes, `routeTree.gen.ts` regenerated by the Vite plugin), vitest + testing-library, Node `node:test` for the script.

**Spec:** `docs/specs/2026-10-30-model-comparison-page-design.md`

## Global Constraints

- Snapshot data file: `packages/shared/src/model-benchmarks.json`; typed module `packages/shared/src/model-benchmarks.ts`; re-exported from `packages/shared/src/index.ts`. (Ruling vs spec: data in JSON so the refresh script rewrites a document, not TypeScript source; the spec's exported names are unchanged.)
- `asOf` is `"2026-10-30"`. `source` is `{ label: "Artificial Analysis", url: "https://artificialanalysis.ai/", version: <the index version the research returned> }`.
- Catalog ids are `${namespace}/${modelId}`; `benchmarkFor` drops the text up to and including the FIRST `/`, lower-cases, and looks up; a bare id (no `/`) is looked up as is.
- Each model version/variant is its own family. Snapshot `ids` are bare provider ids, lower-cased, spelled exactly as `BEDROCK_DEFAULT_MODEL_IDS` and `OPENROUTER_DEFAULT_MODEL_IDS` spell them.
- Quality = round(mean of available parts): `100 * intelligenceIndex / max intelligenceIndex in the snapshot`, and `valetEval.passRate`. Value = round(100 * q²/blended ÷ max over shown rows). Blended = `(3 * input + output) / 4`, only when both prices > 0. Missing inputs mean undefined, never 0.
- Price cells: `formatRate(n)` renders `$0.62`, a third decimal below one cent (`$0.005`), undefined for missing or non-positive. Missing renders as an em-dash-free dash character "–" (U+2013) via a shared `DASH` constant in `lib/model-value.ts`.
- Default sort: Value desc, Quality desc, blended asc, name asc; rows missing the sorted value sort last in both directions.
- Approved column appears only when some row has `approved === false`.
- Routes: `/settings/model-comparison` (personal rail, all members, both modes, label "Model comparison", icon `BarChart3`, after Policies) and `/settings/organization/model-comparison` ("Compare" tab between Models and Proxy).
- Commits: subject ≤ 72 chars, body ends with a `Changelog:` line (CI guard). Spec changes ride in the commit that needs them.
- Before any web test that imports the new shared export: `pnpm --filter @valet/shared build`.

## Review Focus

1. A bare legacy id with no namespace (e.g. `claude-opus-5-5`) must still match its family. Test in Task 1.
2. Bedrock ids with `:` and `.` (`openai.gpt-oss-120b-1:0`) must match exactly, not by prefix. Test in Task 1.
3. A row with an input price but a zero output price shows a dash for Blended and Value, not a number. Test in Task 2.
4. A catalog where no row has a score or a price must render with all dashes and no NaN, and sort by name. Test in Task 3.
5. A filter that matches only by provider name, case-insensitively, keeps those rows; one that matches nothing shows "No matching models." Test in Task 3.
