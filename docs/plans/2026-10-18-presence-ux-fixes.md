# Presence UX Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every finding of the Presence UX review (`presence-ux-review.md`, 20 numbered items): unwired proposal review, misleading sentences, api copy that leaks banned words, silent routine disables, a wizard that defaults to an unconnected service and dumps raw keys, and a copy sweep.

**Architecture:** Five sequential tasks. A: api strings, scheduler reasons, dead-delivery supersession, tool text. B: the sentence renderer and the wizard (words, defaults, picker, schedule step, review). C: the rule and routine pages (proposal review, team gating, Delete, owner marks, one picker). D: redirects, Activity place filter, team Slack channel picker, service-wide names, the copy sweep. E: acceptance and spec. Each task ends green on its suites; the controller runs `make e2e` after E.

**Tech Stack:** Hono api, React 19, TanStack Router and Query, Tailwind, vitest.

**Spec:** `docs/specs/2026-10-16-presence-hub-design.md` (revision 3). Review: `presence-ux-review.md` in the controller's scratchpad (item numbers below refer to the numbered list in the chat report: 1 to 20).

## Review Focus

1. A delivery dead-lettered with the OLD pin text (`Pick another thread for this rule in Presence.`) still renders as a pin problem with the picker (Task A keeps the old string in the web's match; Task A test).
2. An org mention line viewed by a member who is not its creator reads `When <creator> mentions Valet…`, never `When you…` (Task B test).
3. A routine disabled by the scheduler for a deleted workflow shows `Morning summary is off: its workflow was deleted.` in Needs attention with an Edit link (Task A + Task C test).
4. The wizard opened with no integration connected lands on `On a schedule`, with the Slack/GitHub/Linear When choices disabled and each labeled `Connect <service> first` (Task B test).
5. `/workflows?tab=triggers&review=<event rule id>` opens `/presence/rules/<id>`; the same URL with a schedule id opens the routine page (Task D test).
