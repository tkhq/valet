# Engine v2 Phase 5 — Workflow Run Host (Local) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Durable structured automation on the engine substrate — a portable checkpointed interpreter over `dag/v1` that spawns sessions, awaits schema-validated results, parks on approvals and timers, and survives kill/restart at any point without duplicate external dispatch.

**Architecture:** A new portable package `@valet/workflow` holds the dag/v1 definition types (lifted from `main`), the expression engine (lifted verbatim), a `WorkflowStore` port with in-memory reference implementation, the checkpointed interpreter (`driveUntilPark`), node executors, the `LocalRunHost` (leased worker loop + timer scan + lost-wake sweep), and exported conformance suites. `packages/api` implements the store over the app SQLite DB (0000 edited in place), wires engine deps over `EngineHost`, exposes REST routes, and routes approval attention through the Phase 4 notification system. The engine activates `resultSchema` in `awaitResult`.

**Tech Stack:** TypeScript, Node 22, better-sqlite3 + Drizzle, `@sinclair/typebox`, Hono, Vite/React 19, vitest, pi-agent-core/pi-ai pinned 0.73.0.

**Source specs:** `docs/specs/2026-07-11-workflow-run-host-design.md` (checkpoints, signals, parking, ownership, RunHost port, conformance — the authoritative contract). `docs/specs/2026-05-02-portable-runtime-engine-design.md` §1481 Workflow Caller Contract, §407–422 `awaitResult`/`SubmissionResult`. dag/v1 semantics reference: `main`'s `packages/shared/src/types/workflow-dag/` + `packages/worker/src/workflows/runtime.ts` (read via `git show main:<path>`). Roadmap: `docs/plans/2026-07-11-engine-v2-local-e2e-roadmap.md` Phase 5.

## Locked Design Decisions

The specs leave gaps; these are decided. Do not re-open them mid-task — flag concerns to the coordinator instead.

1. **Package layout:** `packages/workflow` (`@valet/workflow`), exports: `.` (types, interpreter, executors, LocalRunHost, in-memory store), `./conformance` (suites, mirroring `@valet/engine`'s conformance export pattern).
2. **dag/v1 subset lifted from main:** `shape.ts` (WorkflowDefinition/WorkflowEdge/WorkflowPolicy/WorkflowTriggerPayload — drop `ui`/WorkflowEditorState) and node interfaces for `trigger`, `set`, `if`, `wait`, `approval`, `session`, `stop` into `packages/workflow/src/dag/`. Drop all `NodeDocs` objects and `createDefault*` factories (editor concerns). `WorkflowNode` is the union of the seven supported types; `version: 'dag/v1'` literal retained.
3. **Session node is start-mode only this phase.** Fields kept: `id`, `type: 'session'`, `mode: 'start'`, `prompt`, `title?`, `model?`, `outputSchema?` (JSON Schema object), `wait?: { mode: 'none' | 'until_idle'; timeout? }`. Dropped from main's shape: `workspace`, `personaId`, `repairModel`, `resultMode`, `repo`, prompt-mode (all deferred; repo/persona need Phase 6 platform pieces).
4. **Expression engine lifted verbatim:** main's `packages/worker/src/lib/workflow-dag/expression.ts`, `if-operations.ts`, `duration.ts` (+ `expression.test.ts`, `template-lint` NOT lifted) into `packages/workflow/src/dag/`. These are pure modules; change only import paths. Template resolution context: `{ trigger, nodes }` where `nodes.<id>.output` is the node's checkpoint `result`.
5. **Lean validator written fresh** (`packages/workflow/src/dag/validate.ts`, not main's 1349-line one): version literal, unique node ids matching `/^[a-z0-9][a-z0-9_-]{0,63}$/i`, exactly one `trigger` node with no incoming edges, all edges reference known nodes, `fromOutput` only on edges leaving `if`/`approval` nodes, no cycles (DFS), only supported node types, `wait.duration`/`approval.timeout` parseable by `parseDurationMs`. Returns `{ ok: true } | { ok: false; errors: string[] }`.
6. **WorkflowStore port** (`packages/workflow/src/store.ts`) — exact types from the run-host spec (`NodeCheckpoint`, `RunParkState`, `RunSignal`, `RunParams`), plus a `WorkflowRun` row type = RunParkState + `params`, `definition` (snapshot), `definitionVersionId`, `attempt`, `wakeAt?`, `wakeRequested`, `createdAt`. Methods: `createRun` (insert-if-absent by id, returns existing), `getRun`, `claimRun(runId, ownerId, leaseMs)` (CAS `pending|parked → running`, increments `attempt`, returns `{ attempt } | null`), `heartbeat(runId, ownerId, leaseMs)`, `parkRun(runId, attempt, waitingOn, wakeAt?)`, `requestWake(runId)`, `scheduleWake(runId, at)` (move-forward: keeps the earlier of existing/new), `beginTerminalize(runId, attempt, outcome)`, `settleRun(runId, outcome)` (idempotent), `listRunnable(now, limit)` (wake-requested, due-timer, or expired-lease runs), `putIntent(cp)` (insert or CAS-replace stale lower-attempt intent), `completeCheckpoint(runId, nodeId, iteration, attempt, terminal)` (CAS from own intent; terminal rows immutable; stale-attempt write → `WorkflowFenceError`), `getCheckpoints(runId)`, `insertSignal` (idempotent by signalId; duplicate returns existing), `consumeSignalAndCheckpoint(signalId, consumedBy, checkpoint)` (atomic: CAS `consumedAt` + write terminal checkpoint in one transaction), `listSignals(runId, { unconsumed? })`, `voidConsumption(signalId)` (re-delivery of consumed-but-uncheckpointed).
7. **Attempt fencing:** the run row's `attempt` increments on every successful claim. Every checkpoint write and signal consume carries the writer's attempt; the store rejects writes whose attempt < the run's current attempt with `WorkflowFenceError`. A higher-attempt `putIntent` replaces a stale `intent` row; terminal checkpoints are immutable (first terminal write wins, late stale terminal writes rejected).
8. **Interpreter** (`packages/workflow/src/interpreter.ts`): `driveUntilPark(runId, attempt, deps)` where `deps = { store, engine: WorkflowEngineDeps, clock, executors, onApprovalPending? }`. The HOST owns claim/lease/heartbeat; the interpreter receives the claimed attempt. Loop: load run + definition + checkpoints + unconsumed signals; if a `cancel` signal exists, abort in-flight submission waits (`engine.abort`) and terminalize `cancelled`; else compute the runnable set; execute executors (writing checkpoints); repeat until (a) a terminal state → two-phase settle (`beginTerminalize` → terminal cleanup → `settleRun`), or (b) nothing runnable → `parkRun` with accumulated `waitingOn` and return the park state. Spurious wakes: load, nothing runnable, re-park — harmless by construction.
9. **Edge/skip semantics (from main's runtime.ts):** an edge is *resolved* when its source node has a terminal checkpoint; it is *active* when the source `completed` AND (`fromOutput` absent or matches the source's boolean output — `if` result / approval `approved`) AND (`when` absent or its expression evaluates truthy). A node is runnable when all incoming edges are resolved and ≥1 is active; a node whose incoming edges are all resolved and all inactive checkpoints `skipped` (propagates downstream). The trigger node's checkpoint result is the `WorkflowTriggerPayload` from `RunParams.input`. Run outcome: `stop` node or all nodes terminal → `completed`; any node `failed` (and unhandled) → `failed`.
10. **Pure executors:** `trigger` (checkpoint the trigger payload), `set` (evaluate template fields → result), `if` (evaluate condition via if-operations → boolean result), `stop` (checkpoint + signal the loop to terminalize with its configured outcome, default `completed`).
11. **Wait node:** parse `duration` → `wakeAt = clock() + ms`; write intent checkpoint carrying `effects: { wakeAt }` (resume reads it back — no re-reading the clock); park `{ kind: 'timer', nodeId, wakeAt }`; on a wake where `clock() >= wakeAt`, complete the checkpoint.
12. **Approval node:** parks `{ kind: 'signal', nodeId, signalType: 'approval:{nodeId}', timeoutAt? }` (timeout via `parseDurationMs`). On first park (intent write), calls `deps.onApprovalPending({ runId, nodeId, prompt, summary?, details? })` — the API wires this to Phase 4's `routeAttention` (kind `approval`, href to the run page). Resolution is a signal row with payload `{ approved: boolean; resolvedBy: string; note?: string }`; consumption is atomic with the node's terminal checkpoint (`consumeSignalAndCheckpoint`). Approved → `completed` with result `{ approved: true, resolvedBy }`; denied or timeout expired → `onDeny` (`fail` default → node `failed`; `skip` → node `skipped`, with `fromOutput: 'false'` edges treated as the deny path exactly like an `if` false branch — for `skip` the node completes with result `{ approved: false }` so false-branch edges activate).
13. **Session node executor** (`packages/workflow/src/nodes/session.ts`): deterministic ids — child session id `wf:{runId}:{nodeId}`, dispatchId `workflow:{runId}:{nodeId}` (repair turn appends `:repair`). Sequence: `putIntent` (effects: `{ sessionId }`) → `engine.createSession({ id, title, purpose: 'workflow' })` (idempotent by id) → `engine.prompt(sessionId, promptText, { dispatchId, model? })` → receipt `{ threadId, queueItemId }` stored in intent effects → if `wait.mode === 'none'`, complete immediately with `{ sessionId, receipt }`; else park `{ kind: 'submission', nodeId, sessionId, threadId, queueItemId }`. On wake: `engine.awaitResult(sessionId, threadId, queueItemId, { resultSchema })` (returns immediately when settled). Outcome mapping: `completed` + valid output → node `completed` with `{ sessionId, response: text, output }`; `completed` + `outputSchema` set + output missing (validation failed) → ONE repair attempt: prompt the same thread (`dispatchId + ':repair'`, `queueMode: 'followup'`) with the schema JSON + the validation error, park again on the repair submission; a second validation failure → node `failed`. `failed`/`aborted`/`superseded` outcomes → node `failed` with the error.
14. **Engine `resultSchema` activation** (`packages/engine/src/thread.ts:2461`): remove the Phase-5 throw. When `opts.resultSchema` is present and the derived outcome is `completed`: extract candidate JSON from the final assistant text — last fenced ```json code block if any, else the whole trimmed text; `JSON.parse` + TypeBox `Value.Check`. Valid → `SubmissionResult.output` set. Parse or validation failure → `output` undefined and `error` set to a compact message including the first few `Value.Errors` paths (outcome stays `completed` — schema repair is a caller concern per engine spec §1481.5). Non-completed outcomes never attempt extraction.
15. **WorkflowEngineDeps** (defined in `packages/workflow/src/engine-deps.ts`, implemented in `packages/api/src/workflows/engine-deps.ts` over `EngineHost`): `createSession({ id, title?, purpose })`, `prompt(sessionId, text, opts) → { threadId, queueItemId }`, `awaitResult(sessionId, threadId, queueItemId, opts) → SubmissionResult`, `abort(sessionId, threadId)`, `isSettled(sessionId, queueItemId) → boolean` (for the lost-wake sweep). The API implementation creates workflow sessions the same way `EngineHost` creates child sessions (Docker sandbox template, owner = run owner, NO `childSpawner` in toolConfig — see `packages/api/src/engine/host.ts` ~476–544), with `purpose: 'workflow'`.
16. **LocalRunHost** (`packages/workflow/src/local-host.ts`, portable): implements the spec's `RunHost` port. Worker loop with concurrency cap 4: poll `listRunnable` every 1s (in-process `requestWake` also nudges immediately), claim (30s lease), heartbeat every 10s while driving, `driveUntilPark`, release. After a park containing `submission` waits, spawn one background waiter per wait: `engine.awaitResult(...)` (no schema, no timeout) `.then(() => wake(runId))` — settlement is the primary wake; waiters are best-effort (crash-lost waiters are covered by the sweep). Lost-wake sweep every 15s (spec bound ≤60s): wakes parked runs with (a) a due timer, (b) an unconsumed signal matching a `signal` wait or a `cancel`, (c) a settled submission wait (via `isSettled`), (d) a consumed-but-uncheckpointed signal (void the consumption first — re-delivery rule). `terminate(runId)`: revoke lease (`attempt`-bump via claim by the terminator), write a `cancel` signal, wake. `start(runId, params)` = `createRun` + wake, idempotent.
17. **App schema additions (0000 edit, Drizzle in `packages/api/src/schema/index.ts`):** `workflow_definitions` (id, org_id, owner_type, owner_id, name, definition JSON, created_at, updated_at), `workflow_runs` (id, workflow_id, definition_version_id, definition JSON snapshot, params JSON, status, outcome, waiting_on JSON, wake_at, wake_requested, lease_owner_id, lease_expires_at, attempt, owner_type, owner_id, created_at, updated_at — the spec's `owner_id` lease field is named `lease_owner_id` here to avoid clashing with the principal owner columns), `workflow_checkpoints` (run_id, node_id, iteration, attempt, status, result JSON, effects JSON, error, created_at, PK (run_id, node_id, iteration)), `workflow_signals` (run_id, signal_id UNIQUE, signal_type, payload JSON, created_at, consumed_at, consumed_by JSON). `definitionVersionId` = sha256 of the canonical (JSON.stringify) definition, computed at run start; the run row snapshots the definition so later definition edits never affect in-flight runs.
18. **Routes** (`packages/api/src/routes/workflows.ts`, mounted `/api/workflows`): `POST /` create definition (validates via `validate()`, 400 with errors), `GET /` list, `GET /:id`, `PUT /:id` (update definition — in-flight runs unaffected per 17), `POST /:id/runs` `{ input? }` → `{ runId }` (runId = `wfrun_` + random; builds `WorkflowTriggerPayload` `{ type: 'manual', timestamp, data: input ?? {} }`), `GET /:id/runs`, `GET /runs/:runId` (run + checkpoints + unconsumed signals), `POST /runs/:runId/approvals/:nodeId` `{ approved, note? }` (writes signal `signalId = 'approval:{nodeId}:resolution'`, wakes), `POST /runs/:runId/cancel` (signal `cancel`, `signalId = 'cancel'`, wakes). All owner-scoped to the authenticated principal like sessions routes.
19. **Web surface (deliberately spartan, controls-complete):** nav link "Workflows" → `/workflows`: definitions list (name, run count, "Run" button) + a JSON textarea create/edit form (no visual editor this phase). `/workflows/runs/$runId`: status header, node checkpoint list (id, status, result preview), pending-approval card with Approve/Deny buttons, Cancel-run button while non-terminal, 5s polling via TanStack Query. Approval notifications (Phase 4 bell) carry `href = /workflows/runs/{runId}`. Every API capability from decision 18 has a control here.
20. **Crash-point hook for the terminalizing test:** `LocalRunHost` accepts `crashAt?: 'terminalizing'` (test-only option, also readable from env `WF_CRASH_AT` in the API boot wiring); when set, the host calls `process.exit(137)` immediately after `beginTerminalize` and before terminal cleanup. Mid-node and parked-on-approval crash points use plain SIGKILL of the child API process (Phase 4 E2E harness pattern).
21. **Duplicate-dispatch assertion:** the E2E asserts via the ENGINE store that each dispatchId (`workflow:{runId}:{nodeId}`) maps to exactly one queue item across all restarts (query `engine_queue_items`/submission rows by dispatchId), and via the workflow store that each `(runId, nodeId, iteration)` has exactly one checkpoint row.

## Exit Criteria (phase gate)

Roadmap Phase 5: “a workflow that spawns a session, awaits a schema-validated result, waits on an approval, and completes — killed and restarted at three different points (mid-node, parked-on-approval, terminalizing) without duplicate dispatches (asserted via dispatchId capture).” Green = Task 12 passing with a real key + Docker, all conformance suites green against in-memory AND sqlite stores, `pnpm typecheck` clean (sanctioned exception aside), and a manual dogfood: create the same workflow through the web UI, run it, approve from the notification bell link, watch it complete.
