Valet has one clear job: receive work, coordinate a session, run the agent in an isolated workspace, and return the result where the work began. Start with that path; use the links below when you need a subsystem's exact contract.

## Boundaries that keep the system legible

<Columns cols={2}>
  <Card
    title="Live coordination"
    icon="workflow"
    href="/engineering/session-lifecycle"
    arrow="true"
  >
    `SessionAgentDO` is the source of truth for connected users, runner
    availability, queued prompts, and in-flight streamed work. It asks the
    backend to create or restore a sandbox when work needs one.
  </Card>
  <Card
    title="Durable state and access"
    icon="shield-check"
    href="/engineering/auth-access-internals"
    arrow="true"
  >
    D1 stores durable application records and R2 stores artifacts. The Worker
    authenticates callers, enforces session access, and issues scoped
    credentials for workspace-facing services.
  </Card>
  <Card
    title="Sandboxed execution"
    icon="terminal-square"
    href="/engineering/runner-and-opencode"
    arrow="true"
  >
    Runner bridges the session protocol to OpenCode. The agent works against a
    real repository and developer tools inside the isolated sandbox.
  </Card>
  <Card
    title="Controlled extension"
    icon="plug-zap"
    href="/engineering/integration-system"
    arrow="true"
  >
    Plugins add tools, channels, skills, and personas. Integration actions
    execute through Valet's policy-controlled Worker path—not directly inside
    the sandbox.
  </Card>
</Columns>
