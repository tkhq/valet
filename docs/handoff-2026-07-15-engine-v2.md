## ⚠️ Critical gotchas (do not skip)

1. **The machine's default kubectl context is a PRODUCTION GKE cluster** (`gke_labrat-glitch-prod...`). Context safety is BINDING: **every** kubectl/helm command pins `--context rancher-desktop` (or `--kube-context`). Never operate on the ambient context. In code, the api's `resolveKubeConfig` throws out-of-cluster without `VALET_KUBE_CONTEXT` and uses `loadFromCluster()` in-cluster.
2. **Node 22 required** for every command: `source ~/.nvm/nvm.sh && nvm use 22 >/dev/null && …`.
3. **PGlite: one instance per process** (WASM heap isn't freed on `close()`). Tests use one shared instance with per-boot `DROP SCHEMA CASCADE`; kill-tests spawn `node --import tsx` directly (never the `tsx` CLI). Dev reset = `rm -rf ~/.valet/pg`.
4. **Transaction discipline (Postgres):** raw `BEGIN`/`COMMIT` through shared `query()` is forbidden — use `transaction(fn)`. Multi-statement fenced writes lock a stable always-present row.
5. **drizzle sqlite idioms (`.get()/.all()/.run()`) compile clean but crash at runtime on pg.** RUN the suites; don't trust tsc alone.
6. **The k8s sandbox identity is the CR, not the pod.** Re-provision goes through `SandboxProvider.release?()` (no-op for k8s → CR re-adopted, workspace survives); terminal `destroy` deletes the CR (cascades PVC). Never delete the CR on recovery.
7. **Root `pnpm typecheck` does NOT cover `packages/web`** — run `cd packages/web && pnpm typecheck` separately. `packages/worker` + `packages/client` are frozen legacy (leave them).
8. Known-allowed failing tests: the 2 `messages.abort.test.ts` cases (pre-existing, deterministic — still owed their own investigation). `sandbox-local` has a `FORCE_COLOR` env flake (run with `FORCE_COLOR=0`).
9. **Pre-1.0 migration rule:** schema changes edit the `0000` files in place + `rm -rf ~/.valet/pg` — no numbered migrations (see CLAUDE.md). Several queue specs add tables; they all follow this.
10. **Stray parent-directory `node_modules` can hijack tsc's `@types` walk.** `/Users/connerswann/code/node_modules` (the repo's PARENT dir has its own package.json) sits on tsc's ancestor-directory search path. A missing `@types/ws` in `packages/api` let tsc find a foreign `@types/ws` up there, which chained to a foreign `@types/node` whose `undici` `Request` clashes nominally with ours (surfaced as `pg-schema.test.ts` Request-not-assignable). Fixed by giving `packages/api` its own `@types/ws` dep (`b9c071fd`). If you see an alien-`@types/node` nominal-type error, suspect this first; new packages that use `ws` (e.g. #2's `sandbox-gateway`) should declare `@types/ws` directly.
11. **vitest does not type-check test files by default** — a test that should fail to *compile* (e.g. passing a not-yet-added field) will still *run green* pre-implementation. For true RED on a type-only change, verify with a temporary `tsc --noEmit`, not just the vitest run. (Hit during #2 T1.)
