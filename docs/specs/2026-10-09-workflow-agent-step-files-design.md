# Workflow agent step input files

Date: 2026-10-09. Issue: TKAI-576.

## Problem

Agent steps receive upstream data through prompt templates. Agents must retype that data to create sandbox files, which wastes tokens and can change values.

## Definition

`session` and `orchestrator` nodes accept an optional `files` map, including inside a foreach body.

```json
{
  "id": "build", "type": "session", "mode": "start",
  "prompt": "Build the dashboard from the input files.",
  "files": {
    "jobs.json": "{{nodes.jobs.result.data}}",
    "notes.md": "Run for {{trigger.data.team}}"
  }
}
```

Keys are literal normalized relative paths. Each slash-separated segment contains only ASCII letters, digits, dots, underscores, or hyphens.
Absolute paths, dot segments, empty segments, backslashes, NUL, and templated keys fail validation.
Accepted keys are already normalized, so alternative normalized spellings cannot collide. Runtime dispatch also rejects duplicate paths.
The map accepts at most 100 files. Other node types reject `files`.

Values must be template strings. The existing template engine preserves single-expression types and uses the node's normal context.
Strings are written verbatim as UTF-8. Other values use `JSON.stringify(value, null, 2)` without an added newline.
Foreach values can read the configured item and index aliases.
File values participate in save-time template lint, runtime audits, and path diagnostics.
Under `policy.onUnresolvedPath: "fail"`, unresolved file paths fail before dispatch, including inside foreach bodies.
Under `empty`, a missing single expression writes `null`. A missing expression in mixed text writes an empty string.

## Dispatch and storage

The portable executor renders file contents into a host-only prompt option. It does not persist these contents in checkpoint effects or results.
The host resolves the execution session through the existing owner and audience routing before writing.
The host calls `attachment.ensureReady` before prompt admission. This provisions a cold sandbox or wakes a suspended sandbox through the normal lifecycle.
It creates parent directories and writes bytes through `Sandbox.writeBinary`, the same primitive used by file uploads.
No shell command carries file contents.

The input root is `<working-directory>/.valet/workflow-inputs/<runId>/<nodeId>/<iteration>/`.
Iteration 0 is explicit, matching existing workflow working-directory conventions. Foreach checkpoint iterations and template indexes both start at 0.
The agent-visible working directory is `/workspace` for container and virtual providers. The local provider uses the session's host working directory.
The host validates dispatch ID segments and rendered relative keys. It resolves each destination and checks containment under the input root.

The host appends a generated manifest after the delivered author prompt and any existing output contract.
The manifest lists absolute paths and exact UTF-8 byte sizes. It tells the agent to read workflow input data from disk.
Paths are generated by the host, not injected through template context.

Named limits are 10 MiB per file and 25 MiB per node. Both executor and host check byte sizes before any write or prompt admission.
A limit error names the file, its size, and the cap. Sandbox preparation and write failures fail the node with a corrective action.
A partial write cannot admit the agent. A new run can retry the failed node's work.

## Durability

The existing intent checkpoint precedes input writes and prompt admission.
If a crash occurs before the receipt checkpoint, re-dispatch renders the same upstream results and rewrites the same paths and bytes.
The engine deduplicates the submission by its existing dispatch ID. No input contents or extra file state enters checkpoints.
Once the receipt exists, resume checks that submission instead of starting another turn or rewriting files during its work.
Format repair uses the same sandbox and existing inputs. It does not require a second manifest.
Run-scoped directories prevent personal and legacy assistant runs from overwriting each other's inputs.
Input retention follows the owning sandbox's existing lifecycle. This feature adds no cleanup timer or reverse output-file interface.

## Real constraints

The repository is cloned at `/workspace/valet`, not directly at `/workspace`.
The architecture overview describes sandbox-less orchestrators. Current runtime code provisions their sandboxes lazily and supports readiness before admission.
New team workflow reports use isolated execution sessions. Personal, attended, and retained legacy routes can share a sandbox, so run scoping remains required.
Definition action schemas intentionally use unknown payloads. The common definition linter validates full saves and node patches; no separate node schema needs expansion.
The web editor preserves complete node objects. Tests pin file preservation across inspector edits and canvas projection.

API tests use PGlite, VirtualSandboxProvider, and a faux model transport to inspect files before the first model call.
Tests also cover foreach directories, shared assistant runs, replay without a receipt, write failure before admission, and unchanged checkpoint effects.
